# Phase 2, sub-project 1: test evaluation (detection quality and benchmark)

Rubric line: "Evaluate system performance on the validation dataset (50 claims) achieving high Macro F1 across rule
categories and preserving valid claims (low false-positive rate)." Deliverable: test evaluation report (detection
metrics, F1, false-positive rate, latency, limitations).

## Goal
Compute detection metrics on as many labelled examples as the repo can honestly supply, keep every example traceable
to its origin, and write the report. Widening the sample is only worth it if each number says where its label came from.

## Non-goals
Changing the rules, the engine or `src/evaluate.py` (it stays the organizers' scorer). Live-model evaluation (the AI
step keeps its own report in `docs/17` and `docs/21`). The login, routing and security work (later sub-projects).

## Example sets and where each label comes from
Labels differ in trustworthiness, so sets are grouped into three evidence tiers and **never pooled across tiers**.

| Tier | Set | Claims | Label origin |
|---|---|---|---|
| A: organizer key | S1 `data/development` | 400 | `expected_results.jsonl`, organizers' dataset v1.0.0 (`data/dataset_manifest.json`, 2026-09-17, synthetic) |
| A | S2 `data/validation` | 150 | same |
| A | S3 `data/stress` (the 50-claim split) | 50 | same |
| A | S4 handbook worked cases `examples/worked_cases.json` | 10 | handbook, organizers; de-duplicated against S1 to S3 |
| A | S5 the same 600 claims as FHIR bundles `data/*/fhir_bundles.jsonl` | 600 | organizer key; tests the FHIR path; known documented loss: FHIR carries no authorizations, so R009 becomes `UNABLE_TO_ASSESS` |
| A | S6 the same 600 claims as CSV folders `data/*/csv` | 600 | organizer key |
| B: independent oracle | S7 generated claims (`tests/claim_gen.py`, `scripts/status_coverage.py`, seed 20260927; 108,726 attempted, 107,635 pass the transport check) | 107,635 | `tests/oracle.py`, our second implementation written from `docs/04` alone |
| B | S8 boundary-aware mutants of real claims (mutator from `tests/test_stress_differential.py`), regenerated by the new script from fixed seeds, target 37,000 before the transport filter | stated in the run | oracle |
| C: hand-derived | S9 boundary table `tests/test_stress_boundaries.py` | 123 | derived by hand from the wording of `docs/04` |

The 37,000-mutant figure in `docs/19` came from a run no committed script reproduces, so it is not cited; S8 is regenerated and its real count reported.

Honest reading of the tiers. Tier A is the only external truth. Tier B measures **agreement** between two
implementations written by the same team from the same text, so a shared misreading would not show; it is reported as
agreement, not accuracy. Tier C is small and written by us.

## Provenance (the citation requirement)
`scripts/evaluate_phase2.py` writes `outputs/evaluation/provenance.json`: for every set, its name, claim and result
counts, label source, generator script and seed or command, file path, SHA-256 of the file, git commit, and known
limitation. Each claim is also tagged with its set id in the run output. Claims that appear in several sets are
de-duplicated by a canonical hash within a tier, and the overlap is reported. The report cites a provenance entry for
every table.

## Metrics
Positive class: `FAIL` (matches `src/evaluate.py`). `UNABLE_TO_ASSESS` is scored separately, because abstaining is not
an error but an unnecessary abstention costs a reviewer time.
- Precision, recall and F1 per rule (undefined when a rule has no `FAIL` in a set; excluded from the macro and
  listed).
- **Macro F1 across rule categories.** The rulebook defines no categories, so these are ours, by what the rule checks:
  completeness and arithmetic (R001, R007, R012); eligibility and coverage (R003, R004, R005, R015); timing (R002,
  R014); authorization and documentation (R008, R009, R010); catalogue, pricing and duplicates (R006, R011, R013).
  Also reported macro by severity (high 11 rules, medium 4) and macro over all 15 rules, so the grouping choice cannot
  flatter the result.
- Multi-class view: macro F1 over the four statuses, which includes abstention quality.
- **Preserving valid claims.** Claim-level false-positive rate: among claims whose gold has no `FAIL`, the share where
  the engine raises at least one `FAIL`. Also among fully clean claims (all `PASS` or `NOT_APPLICABLE`: 201 in the
  public splits), the result-level false-alarm rate, and the false-abstention rate.
- Uncertainty: with few or no errors a bootstrap interval is degenerate, so report exact (Clopper-Pearson) upper
  bounds on the error rate and say what sample size would be needed to claim a lower one.
- Baselines so the metric can discriminate: always-`PASS`, and the plain-Python baseline (`src/run_baseline.py`).
- Latency: engine per claim p50, p95, p99; ingestion plus engine; the audited path with the template; the AI step
  quoted from the recorded live runs (`outputs/defense/load.json`), not re-run, with its n.

## Components
- `src/eval_metrics.py`: pure functions only (confusion counts, F1, macro, claim-level FPR, exact bounds); unit-tested
  on small hand-checkable matrices.
- `scripts/evaluate_phase2.py`: loads each set, runs the engine, scores, writes `outputs/evaluation/metrics.json` and
  `provenance.json`; deterministic (fixed seeds), one command.
- `docs/29_Test_Evaluation_Report.md`: the deliverable, with a limitations section and provenance citations.

## Success criteria
One command reproduces every number in the report; each table cites a provenance entry; metric functions are tested
against hand-computed cases; the existing 523 tests still pass; limitations name what the sets cannot show (all
public splits score 1.0, so F1 there cannot rank this system against a better one; the oracle shares our reading of
the rulebook).

## Risks
Tier A will score 1.0 everywhere, which looks suspicious without the baselines, the bounds and the harder tiers next to
it; the report must show why that is expected (the answer key is deterministic and the rules were built against it).
If any set disagrees with the engine, the disagreement is reported and investigated, not tuned away.
