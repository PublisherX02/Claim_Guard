# Identity and Access Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Badge + password + TOTP login, four clearance levels, a hide-not-disable reviewer API with decisions bound to the authenticated badge, a security audit log, and a stress and attack suite, per the spec.

**Architecture:** A `src/access/` package of small modules (permissions, config, passwords, totp, tokens, store, store_mongo, securitylog, service, masking, claimstore, api). The service layer holds all rules and never touches HTTP; the API layer only translates. Storage sits behind a `UserStore` interface with an in-memory twin and a MongoDB implementation, both proven by one contract suite. Claims stay in the existing JSONL outputs behind a `ClaimStore`.

**Tech Stack:** Python 3.10 to 3.14; `fastapi==0.142.2`, `starlette==1.7.0`, `uvicorn==0.54.0`, `bcrypt==5.0.0`, `PyJWT==2.15.1`, `pyotp==2.10.0`, `cryptography==50.0.2`, `pymongo==4.18.2` (runtime); `httpx==0.28.1` (dev); `unittest`, Hypothesis; MongoDB 7 in Docker.

**Spec:** `docs/superpowers/specs/2026-10-04-identity-access-design.md`

## Global Constraints

- Server dependencies are pinned in `requirements.txt` (runtime) and `requirements-dev.txt` (httpx); the offline engine, the evaluation and the existing tests must keep working without importing `src/access`.
- No secret, password, TOTP seed, TOTP code or token is ever logged, audited, returned after creation, or put in an exception message.
- `scripts/` and `src/` must not contain the sink words of `tests/security_sinks.py` (`subprocess`, `pickle`, `marshal`, `shelve`, `os.system`, `os.popen`, bare `eval(`, `exec(`, `compile(`, `input(`, `__import__(`), not even in docstrings. Use `getpass` for passwords. `bandit -r src scripts -ll` stays clean.
- Run single modules with `python -m unittest discover -s tests -p <file>` (the dotted form does not work here). Use `.venv/Scripts/python.exe`.
- Test settings use `bcrypt_rounds=4`; production default and minimum is 12. Mongo tests read `MONGO_URI`; with `REQUIRE_MONGO=1` (set in CI) a missing URI is a failure, otherwise a loud skip.
- Existing 618 tests keep passing. Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and the `Claude-Session:` line. Do not push without being asked.
- Stage files by explicit path and show `git add` errors; `outputs/` needs `git add -f`.

## Review Focus

- A forged or stale token must never grant more than the database says today: level and permissions come from the store on every request.
- One TOTP code must authenticate exactly once under parallel submissions, on both stores.
- A client must never be able to choose the reviewer recorded on a decision, the original status, or any user field it was not meant to set (mass assignment).
- Unknown badge, wrong password, locked and inactive accounts must be indistinguishable by body and (statistically) by time.
- Anything in a response that a level may not see must be absent, including raw identifiers inside free text and evidence.
