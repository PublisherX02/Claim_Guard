# Extension Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native execution chosen by the user: "do things your way").

**Goal:** Eight advisory rules (E001 to E005, E101 to E103) in a separate pack, schema, module and output, proven not to disturb the
official fifteen.

**Architecture:** `src/extension_rules.py` mirrors the official engine's design (details function per rule emits fact lines and
result fields from one pass; a YARA-X pack, generated by `pack_source()` and committed as `rules/extensions.yar`, matches the
blob). Catalogue attributes live in `rules/extensions/catalogue.json`. Earlier-claim data comes through `src/claim_history.py`.

**Tech stack:** Python 3.10+, yara-x (already pinned), Hypothesis (dev), unittest.

**Spec:** `docs/superpowers/specs/2026-10-04-extension-rules-design.md`

## Global constraints
- Official files untouched (hash-pinned in `tests/fixtures/extension_baseline.json`, recorded at commit `7e862d6`'s parent code).
- Ids `E001..E005`, `E101..E103`; `rule_source` `fictional-extension/<id>@1.0.0`; `rule_version` `1.0.0`.
- Missing input gives `UNABLE_TO_ASSESS`, trigger absent gives `NOT_APPLICABLE`; an exception inside a rule gives `UNABLE_TO_ASSESS` for it alone.
- Fictional codes: services `SVC-EXT-PRIMARY`, `SVC-EXT-COMPONENT`, `SVC-EXT-NEVER`, `SVC-EXT-RX`; diagnoses `DX-EXT-ACCIDENT`, `DX-EXT-SECONDARY`.
- "Earlier claim" = same non-empty `patient_id`, different `claim_id`, `(submission_date, claim_id)` strictly smaller.
- Stage explicit paths when committing; run tests with `python -m unittest discover -s tests -p <file>`.

## Review focus
Hostile notes imitating a fact tag; equal submission dates (tie order); the claim's own id inside history; quantities as strings,
floats and Decimals; a claim with no lines; an authorization id with no record; 10,000-claim history performance.

### Task 0: Baseline and separation tests
Files: `tests/fixtures/extension_baseline.json` (create), `tests/test_ext_separation.py` (create).
- Record SHA-256 (CRLF-insensitive) of the nine official files and of the canonical official results for every claim in
  `data/*/claims.jsonl`. Tests: official files match; official results match; `extension` ids never start with `R`; official scorer
  rejects an extension result record.

### Task 1: Catalogue, schema, history
Files: `rules/extensions/catalogue.json`, `schemas/extension_result.schema.json`, `src/claim_history.py`, `tests/test_ext_history.py`.
- Tests: ordering and ties, self-exclusion, same claim id never history, other patients excluded, empty patient id gives no
  history, input not mutated, catalogue labelled fictional and every flagged code is outside the official catalogue.

### Task 2: Engine core plus E001, E002
Files: `src/extension_rules.py`, `rules/extensions.yar` (generated), `tests/test_ext_rules.py`.
- Tests table-driven: pass, fail, not-applicable, unable per rule; engine isolation; pack file equals `pack_source()`; result
  record validates against the schema; evidence pointers resolve; forged fact tags in notes create nothing.

### Task 3: E003, E004, E005
Same files. Boundaries: event date equal to / after the earliest service date; invalid calendar date; two event dates; route
modifier present / absent / unknown; secondary diagnosis.

### Task 4: E101, E102, E103
Same files plus history fixtures. Boundaries: exactly at the authorization maximum and one over; earlier units zero versus positive;
different provider; same claim id re-submitted; missing history gives unable; tie in submission date.

### Task 5: Independent oracle and cross-check
Files: `tests/oracle_extensions.py`, `tests/test_ext_oracle.py`. Hypothesis-generated claims and histories compared with the engine
on status, affected lines and evidence paths.

### Task 6: Fuzz and mutation checks
Files: `tests/test_fuzz_ext.py` (also added to `scripts/fuzz_campaign.py` SURFACES); mutation script in the scratchpad.
Each mutant (own units counted twice, order ignored, exception modifier ignored, provider ignored, boundary `>` to `>=`, forged
tag accepted) must be caught by a test.

### Task 7: CLI and experiment
Files: `scripts/run_extensions.py`, `scripts/extension_experiments.py`, `tests/test_ext_cli.py`, `tests/test_ext_experiments.py`,
`outputs/evaluation/extensions.json`. Deterministic output; fire counts on the 600 public claims; runtime with a 10,000-claim history.

### Task 8: Documentation
Files: `docs/30_Extension_Rules.md` (a card per rule: logic, source and whether confirmed, invented attributes, false-positive
risks, example), README section, SPECS section 10e, test counts in README, SPECS, docs/17, docs/27; CI picks the new tests up
automatically (`discover`).

### Final
Whole-branch review by a fresh reviewer on the most capable model; one fix pass; matrix on Python 3.10, 3.12 and 3.14.
